# E1 · DQN 完整配方基线（15×15）——失败实验档案

> 课 01 第二刀。状态：**结课·失败档案**（2026-09-07）。
> 这份笔记记录的是"为什么没训出来"，不是"训出来长什么样"。
> 颠沛流离的完整过程见 `../learning-journey.md` #01，本文是诊断结论层。

## 问题

在 3×3 表格 Q 概念验收（E0）之后，把事实度最高的验证对象换成 15×15 大棋盘上的
标准 DQN，作为整节课的基线对照组。要回答的核心问题：
**vanilla DQN 在纯稀疏奖励 + 固定对手下，到底能不能自己学会五子棋？学多快？**

## 设置

- **网络**：2 特征平面（己方/对方）小 CNN → 225 Q 值；replay buffer + target network +
  ε 线性退火；Adam；步/学 4:1 节流；target 每 1 万步同步。
- **对手池**：黑方学员自弈，白方在 random 与 minimax-easy 间轮换。
- **奖励**：纯稀疏终局奖励，赢家 +1 / 输家 -1 / 平 0，中途无塑形。
- **预算**：60 代 / 每代 2 万局 ≈ 120 万局，RTX 5060 Ti。
- 逐代基准赛：vs random / minimax-easy 各 20 局。

## 你应该会看到（D2 预测）

胜率曲线长期贴地、平均局长先变长（学会拖延）再变短；若干代后对 easy 胜率开始爬升。

## 实测（实际发生了什么）

| 指标 | 表现 |
|---|---|
| loss | 第 4 代爆到 ~1e22，之后缓慢回落仍达 ~1.3e22 量级 |
| 策略熵 | 恒 -0.0（电路过早收敛进一个确定性垃圾策略）|
| 对 easy 胜率 | 前 3 代 1.0，第 3 代起跳崖到 0.0 |
| 平均局长 | 79 → 77（**终局分布几乎没动**：没学会"把棋下完"）|
| 吞吐 | 7.6h 才 8/60 代（≈1h/代，60 代 ≈60h）；GPU 13%、CPU 单核满 |
| 训练进程 | era 9 时自行死掉，第二天才察觉 |

曲线的直观含义：**它一晚的"学习"全落到一个确定性垃圾策略上**，既没学会赢，
也没学会拖延到胜局。走 77 手 = 往棋盘填 77 个格子然后赌平局。

## 反例（根因，为什么没训出来）

三个根因，互相缠绕，**没有一个属于"调参"**：

1. **稀疏奖励 + 致命三要素**：一局 ~78 手只给终局 ±1。DQN 的自举 + 函数近似 + 异策略
   三个要素叠在稀疏信号上，值没法沿长决策链传回。这是 vanilla DQN 在这里的**硬下限**，
   "等更久"无效——E10 奖励塑形 / E11 行为克隆预训练才是正解（原大纲已排在后面）。
2. **对手是坏的（minimax-easy 符号 bug）**：`minimax.py` select_move 多一层负号，
   把必胜手算成 -WIN 而拒吃。对 easy 的"胜率崩塌"很大程度是**拿一个坏对手当标尺**，
   结论失真。这同时污染了难度曲线与信号密度的解读。
3. **零可观测性**：全程 stdout 静默，曲线 PNG 等 60 代跑完才出，崩溃无 resume。
   "卡死 vs 慢"当时无从区分，只能等天亮再被动开图。

（吞吐瓶颈顺带给后续中医药：minimax-easy 一步 12.7ms 占 ~89% 手成本，是纯 Python
 搜索，不是 GPU 也不是 Python 循环。）

## 结论

**vanilla DQN 在纯稀疏 + 坏对手 + 零可观测下，不学习，且不可诊断。** E1 的验收结论
是"失败"，但它作为一次失败实验，把下一轮该往哪走照得清楚：

- 环境层（本轮）：吞吐量 + 可观测性重塑——换掉 minimax 对手、推理退 CPU、
  实时日志 + 每代刷曲线 + checkpoint/resume。
- 训练层（下轮）：稀疏信号（信用分配 / 塑形 / 预训练）、信号密度、难度曲线，
  并修 minimax 符号 bug。
